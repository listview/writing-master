# 写作大师

一个面向中文小说与商业化网文的 Codex 写作技能。

写作大师把“好读”拆成可执行的工作：先确定本章主问题，再用清晰的因果链、可辨识的人物声线、公平的信息差和有代价的结果推动故事。它可以从零创作，也可以在不破坏已发布事实的前提下续写、诊断和重写已有文稿。

## 适用范围

- 长篇小说、短篇小说与连载网文
- 玄幻、仙侠、科幻、都市、现实、言情、历史、悬疑、志怪、轻喜剧等题材
- 选题与长篇架构、章节大纲、正文续写、旧稿优化、连续性诊断
- 单章处理或带项目总档的长期创作

题材只是外层。写作大师的通用层负责因果、节奏、人物、信息与兑现；世界规则、专名、时间线和人物状态必须来自用户提供的项目资料。

## 核心方法

1. 让读者尽快知道人物在哪里、想要什么、为什么暂时得不到。
2. 用“目标 → 阻碍 → 判断 → 选择 → 行动 → 结果 → 代价/新条件”检查因果，不把内部检查表硬写进正文。
3. 每章确定一个主叙事发动机和一个主问题，避免多线平均用力。
4. 设定在人物需要使用时出现，并尽快通过行动、试验或失败接受验证。
5. 让对白争夺结果、时间、利益、责任或关系，而不是轮流讲解背景。
6. 每章兑现至少一件可核验的事，并改变一个具体条件。
7. 优先降低阅读负担，不靠堆辞藻、连续解释、无效微动作或模仿特定作者来制造质感。

## 快速开始

在 Codex 中显式调用：

```text
使用 $writing-master，续写下面这章。先读取项目总档和最近两章，保持人物状态与物件归属连续；本章主问题是……
```

从零创作时，建议提供：

- 一句话卖点和目标读者
- 当前题材与希望的叙事气质
- 主角的眼前缺口、长期欲望和能力边界
- 已确定的世界规则、人物关系和不可修改事实
- 本次要交付的形式（大纲、章节卡、正文、诊断或重写）

续写或优化已有作品时，优先提供：

- 项目总档（推荐命名为 `00_项目上下文总档.md`）
- 当前章节和最近一至三章
- 必须保留、不得改变和希望加强的内容

完整使用示例见 [`docs/usage.md`](docs/usage.md)。

## 设计边界

- 不复刻在世作者的标志性句式、独特桥段或可识别声线，只提取可迁移的叙事机制。
- 不把示例作品、示例人物或示例世界规则写入用户项目。
- 不把候选正文中新出现的事实自动写入权威项目档；状态变化应先标为草稿，经过用户确认再接受。
- 不替代历史、法律、医学、行业和事实核验。
- 处理用户已有文本时，以用户明确要求、已发布正文和项目档为优先约束。

## 开发与校验

修改 `SKILL.md` 或参考文件后，建议运行技能校验脚本：

```bash
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py .
```

校验通过只说明文件结构和元数据有效，仍应使用真实的创作请求检查输出质量。
